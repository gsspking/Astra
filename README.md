# ASTRA Studio

Open `index.html` in a current browser, or serve it with a static HTTP server. The application remains a single self-contained HTML file; Node.js is only used for regression tests.

- Home combines the project overview with production metrics, stage progress, the scene/shot heat map and film timeline. Old Dashboard links redirect to Home. Use Upload banner / Change banner on the top image to save a banner for the current project, or Reset banner to restore the default. Banners are separate from project thumbnails and included in full project backups.
- Layouts adapt automatically: phones below 768px use bottom navigation and a full workspace drawer; tablets from 768–1199px use an icon rail; larger screens use the full sidebar. Phone asset editing switches between the library and a focused inspector, production opens as shot cards, and screenplay views have separate reading, source and scene-list tabs. PDF preview can fit the page or pan at actual size; print output keeps its original dimensions. Forms and controls use larger touch targets on compact screens.
- Choose Reposition banner to drag the image with a mouse or touch, adjust the position sliders, or fine-tune with arrow keys. Save position commits the crop; Cancel reposition or Escape discards the preview. Positions are stored per project and included in backups, with centered defaults for older projects.
- Projects autosave to IndexedDB after edits. Optional folder mirrors run after three seconds without edits. Save errors are shown, and the Saved timestamp advances only after a successful write.
- Script accepts Final Draft `.fdx`, Fountain, Markdown and plain text. The default Screenplay view uses screenplay-style action, character, dialogue, parenthetical and transition positions, with source scene labels on both margins. FDX imports retain paragraph types, bold/italic/underline runs and dual dialogue. Edit source remains available; saved script versions preserve imported formatting.
- Raw Scene Count is the total number of scene headings. Script scene labels such as `1`, `1A`, `1B`, `4A` and `4B` are stored separately from numeric ordering and carried through analysis, breakdown links, scene filters, shot codes and exports. Fountain `#1A#` markers and prefixed scene labels are supported. Unnumbered headings use automatic sequential labels.
- Script analysis retains existing shot edits, approvals, media and asset records. Scenes outside the current screenplay move to Retained production scenes, excluded from active counts. Their shots remain in backups, can be exported separately from Script, and return when those scenes are reintroduced. An analysis response is rejected if the project changed while the request was running.
- Generation templates support `{{fps}}`, `{{duration}}`, `{{frames}}`, `{{num_frames}}` and `{{frame_count}}`. FPS comes from Project Setup; duration comes from the target shot. Asset-only generations default to three seconds. Frame counts are rounded from FPS × duration; individual model workflows may require their own frame-count adjustments.
- Local images and videos are stored once as content-addressed blobs, with lightweight references in project history and snapshots. Existing embedded-media projects migrate when opened. Full JSON downloads and folder mirrors include local media as data URLs for portability. Imported remote URLs remain remote references.
- Settings → Reclaim unused media removes files unreferenced by any saved project, current undo/redo history or snapshot. Newly attached media is protected briefly while saves settle. Optimize storage retains approved/latest shot versions and versions pinned as scene heroes; retained history and snapshots still keep their media until those references are removed.
- Storyboard/PDF shot codes sit above the top-left edge of each frame, including when captions are hidden or placed to the right. WebM shot codes and action text use a separate 32-pixel top header so the picture stays unobstructed; the picture area preserves the project aspect ratio.
- Production has Collapse all / Expand all controls in both Crux and Flick, plus independent scene toggles. Each scene's focus icon temporarily hides the other scenes and opens that scene for work. Exit focus or press Escape to restore the previous expansion state and page. Crux and Flick remember separate expansion settings for each project in this browser.
- Flick starts with collapsed scene thumbnails. Scene grid / Scene list chooses the overview layout; Thumbnails chooses images, videos or both. Expanded shot cards and collapsed scene details show only the fields enabled in Flick’s Details row, just like Crux’s column controls. These choices are saved per project in this browser, independently of PDF export settings. On phones, swipe the Details row to reach every field. The detail source is identified by shot code; before media exists, the first shot provides the scene's details.
- Use Set scene hero image / Set scene hero video below a shot's media, or in its shot inspector, to pin that displayed version to the scene thumbnail. Without an explicit choice, the first available shot image/video is used. Hero selections survive project backups. Media controls allow upload, generation, approval, version selection and deletion. Deleting a version clears any approval or hero reference to it in one undoable edit; blobs remain protected by undo/history until unused-media cleanup can safely reclaim them. Moving or deleting the hero's shot clears the old scene association.
- Rough Cut exports WebM with available source-video audio, project FPS and full shot durations. Long exports stream to a selected file in browsers supporting `showSaveFilePicker`. Other browsers use a 64 MB output buffer and stop with an explicit error if it fills. Export runs in real time, can be cancelled, and reports media failures. Sound-cue text is metadata; no dialogue or soundtrack is synthesized. WebM reviews are not finishing masters.

## Regression tests

Requires Node.js, Chromium, FFmpeg and ffprobe. Install test dependencies with `npm ci`. Set `CHROMIUM_PATH` if Chromium is not at `/usr/bin/chromium`.

```sh
npm test
npm run test:long
```

The long test records and inspects a real 181-second streamed WebM. Tests cover screen navigation, idle saves, folder mirroring, save failures, reanalysis, media deduplication/migration/cleanup, portable backups, generation request variables, audible source audio, aspect ratio and export cancellation. Responsive checks exercise every workspace at 320, 390, 600, 768, 820, 1024 and 1440px, plus drawer keyboard focus, touch asset editing, orientation changes, PDF sizing, and touch/keyboard banner positioning. Provider requests are intercepted fixtures; real installed LLM/ComfyUI models are not required. Test outputs are written under ignored `test-results/`.

Import / Export → Example Project provides [example_project.json](example_project.json), [llm_instruction_prompt.md](llm_instruction_prompt.md), and [project_schema.json](project_schema.json), also embedded in the standalone HTML. Give these files and your screenplay to an external LLM to produce a complete native project JSON, then review and apply it with Replace whole project. Projects → New project → Start from the example film uses this same complete example, with its shot budget fitted to the chosen target. The example covers every project section: metadata, formatted screenplay/history, detailed characters/locations/props/costumes, references and angles, scene production notes, all shot planning and image/video prompt fields, skills, versioned demo media and scene heroes. Its six shots total exactly one minute. The labelled reference images and one-second color-card video are illustrative media; the instructions require replacing them with actual media or empty media slots for a new film. Connections, credentials and browser view preferences are configured separately.

Import review validates IDs, asset and angle ownership, media approval/hero links, positive durations and scene order, and reports source-scene or runtime differences. Project Setup shows target and combined shot runtime. Fit shot durations to target distributes the available whole-frame budget across active shots, preserves their relative timing as closely as possible, and supports Undo. Review pacing and video-prompt timing after fitting.

Image, video, negative, asset and angle prompt boxes have a Copy control on hover or keyboard focus; touch devices show it directly. Copy controls also appear in generation dialogs, Crux prompt columns and Flick prompt details. Copying preserves the full prompt, including line breaks and non-English text, without changing the project.
